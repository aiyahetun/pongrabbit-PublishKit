| 产品边界 | 本地内容资产和发布台账。用户仍在各平台自己的发布页粘贴。不接平台账号，不代发 |

0.3.5 定案：

- 一条内容只存一种语言。中英都标了字段的块，导入时拆成一对，用 `pair_id` 连着。各渠道任务共用这一条的标题、正文、关联词。
- 今天、日历、插件里的今天列表看全部项目，并写出项目名。内容库和素材库只看当前项目。
- 关联词只认明确标签，包括同行 `**关联词：**` 和换行的 `**标题（中文）**` / `**正文（中文）**` / `**关联词（中文）**`，以及英文 Title / Description / Keywords。不猜文末。认不出就留空。
- 渠道仍是全库共用。免费版可以建多个项目，内容条数仍是 50。
- 每个项目有自己的文案、图片、视频目录。移动或删除项目只改库里的归属，不搬、不删磁盘文件。移动内容时，关联图的索引跟着走；同一路径可以在两个项目里各有一条索引。
- 小红书、Pinterest、公众号、YouTube 的「复制正文」不含关联词。其余渠道（含自定义渠道）在正文后空一行再接关联词。「复制关联词」始终单独一个按钮。
- 大图先读文件头里的宽高。估算解码超过 48MiB 就不再整图解码，改用系统缩略图。失败时卡片仍显示文件名、像素和大小，并可以打开原图、继续关联。

## 1. 别人怎么拆，我们取哪一种

看的是「多品牌怎么隔开」「一条帖子的标题、正文、标签怎么分开拿」「大图列表怎么预览」。调度器的自动发帖不在采用范围内。

| 产品 | 他们怎么做 | 出处 | 发稿匣采用的部分 |
|------|------------|------|------------------|
| Planable | 一个 workspace 只放一个客户或品牌。日历、稿件、素材都在这个空间里，换空间才看另一家 | [Workspaces](https://planable.io/guides/planable-workspaces/)、[多客户设置](https://help.planable.io/hc/en-us/articles/21715390472348-Setting-up-accounts-for-multiple-clients) | 工作时默认只看当前产品。换产品用切换器，不靠记忆和文件夹名 |
| Typefully | Social Set 一换，草稿、日历、设置一起换。个人号、公司号、客户号各一套 | [Accounts FAQ](https://support.typefully.com/en/articles/8717684-accounts-faq) | 切换项目时，内容、素材、任务、插件里的今天列表一起换 |
| Eagle | 资源库用 Ctrl+L 切换，可改图标方便认。库内再用文件夹。列表读的是缩略图，宽或高超过 1440px 的 jpg/png/bmp 会另存小图，不解析原图 | [资源库](https://cn.eagle.cool/blog/post/best-practice-for-eagle-library)、[界面](https://cn.eagle.cool/support/article/1-overview-of-library-and-interface)、[缩略图占用](https://cn.eagle.cool/support/article/why-does-the-eagle-library-take-up-more-space-than-the-original-files) | 顶栏切换 + 颜色。预览用小图。不把每个产品做成一份独立数据库 |
| Billfish | 拖进左侧某个文件夹，素材就进那个文件夹。文件夹和标签是两套。索引导入不搬原文件 | [文件夹](https://www.billfish.cn/help/wenjianjiazhengli)、[导入](https://www.billfish.cn/help/daoruhedaochu) | 导入时必须先有目标项目。原文件留在用户目录，库里只记路径 |
| Publer | 同一行 CSV 里 Text 是正文，Title 是另一列。标题只填到 Pinterest、YouTube 等有标题栏的帖子 | [CSV 模板](https://publer.com/help/en/article/what-csv-template-should-i-use-18qhxcq/) | 标题、正文是同一条内容上的两个字段，复制时分开 |
| Buffer | 正文和第一条评论是两个框。标签组可以插入其中一处。他们的设计师写过：用户以前把标签存在备忘录里，发的时候再贴 | [Hashtags](https://support.buffer.com/article/586-how-hashtags-work-in-buffer)、[Hashtag Manager 发布说明](https://buffer.com/resources/hashtag-manager/) | 关联词单独放，不跟正文绑成一次复制 |
| Pinterest 官方发布页 | 上传图之后分别填 Title、Description、Link、Board。Alt text 在 More options 里，又是一栏 | [Create a Pin](https://help.pinterest.com/en/article/create-a-pin-from-an-image-or-video)、[Alt text](https://help.pinterest.com/en/business/article/add-alternative-text-to-your-pins) | 在 Pinterest 任务上，三次复制对应三个框，而不是一段富文本 |
| `image` 0.25 | 解码默认 `max_alloc` 512MiB。超限返回 `InsufficientMemory`，不会自动改成缩小后再解 | [Limits](https://docs.rs/image/0.25.9/image/struct.Limits.html)、[Stack Overflow 上的同类错误](https://stackoverflow.com/questions/71843454/how-to-avoid-insufficientmemory-decoding-error-using-rust-image-crate) | 大图不要整图解码。失败要在卡片上写明，不能变成空白 |

不采用的做法：

- 每个产品一个 SQLite、一套配对码。备份、插件、今天视图会裂开。Eagle 可以这么做，是因为它不管发布台账。
- 只加一个「项目」标签，列表仍默认混合。现在认不出素材，就是因为没有默认隔离。
- 把标题、正文、关联词拆成三条内容或三个任务。渠道台账的粒度仍然是「一条内容 × 一个渠道」。
- 为了预览去调高内存上限，或把原图直接塞进 WebView。大图会再次卡住列表，这是 2026-08-24 素材页卡死的同一类问题。

## 2. 对象关系

一个本地库，里面有多个项目。项目是「一个已经在卖或已经上线的软件 / 网站」。

```text
工作区（一份 publishkit.db，一个插件配对）
  └─ 项目                        例：发稿匣、彭兔子制版、某某官网
       ├─ 名称、颜色、国内品牌名、海外品牌名
       ├─ 文案目录、图片目录、视频目录（可空，可多个）
       ├─ 内容条目
       │     标题 / 正文 / 关联词     三个字段，同属这一条
       │     └─ 发布任务              仍是这条内容 × 某个渠道
       └─ 素材                      图片、视频索引，带宽高和预览状态
渠道（小红书、Pinterest…）留在工作区，各项目共用。
```

当前项目记在设置里，重启后还在。顶栏、内容、素材、来源、任务、日历、插件今天列表，默认都按它过滤。

「全部项目」只是列表的一种看法，数据仍在原来的库里。打开之后，每一行左侧加该项目的颜色点。回到单个项目时，这个点去掉。

今天和日历多一个开关，默认跟随当前项目。旁边放「含其他项目」。一个人一天可能给两个产品各发一条，这个开关就是给这种情况留的，避免为了看另一条又把整个库混回来。

免费版保持 PRD 里的 1 个项目。已有数据迁移出来的那一个不另算。再建第二个项目走 Pro。

## 3. 项目切换与导入归位

### 3.1 顶栏

现在顶栏是一段不可点的名字。改成按钮：

```text
[● 发稿匣 ▾]    搜索    插件已连接
```

菜单内容：

- 各项目一行：颜色、名称、内容条数
- 全部项目
- 分隔线
- 新建项目
- 管理项目（改名、改颜色、改品牌名、改目录、归档）

新建项目只要名称和颜色。目录可以后补。颜色从一组固定色里选，不打开调色盘。归档后的项目不出现在切换器里，数据还在，管理页可以恢复。

已有库第一次打开：用现在的 `projectName`（空则叫「默认项目」）建项目，把现有内容、素材、任务都归进去。不弹复杂向导。顶栏出现切换器之后，设置页原来的「项目名称」改成「当前项目」，避免两处各改各的。

### 3.2 导入必须落在一个项目里

来源扫描、表格导入、素材扫描、手动新建，第一步都显示：

```text
导入到  [● 发稿匣 ▾]
```

默认是当前项目，可以在这一步改。改了之后，这一次导入进新选的项目，并把该项目设为当前项目。

每个项目可以绑自己的目录。扫描只扫这些目录。一个目录只属于一个项目；若用户把已被别的项目占用的目录再绑过来，提示「这个目录已经属于彭兔子制版」，给出「转过来」或「取消」。转过来只改索引上的 `project_id`，不移动磁盘文件。

若几个产品的文件已经在一个父文件夹里，用一次动作处理：在来源页或素材页选「按一级子文件夹建立项目」。每个子文件夹生成一个项目并绑上，名称用文件夹名，用户可以改。这一步是迁移工具，不是日常入口。

内容列表和素材网格支持多选，操作里有「移动到项目…」。移动只改归属。已经挂上的素材关联、发布任务跟着内容走。

同一张图要给两个产品用：允许同一路径在两个项目各有一条索引。`media_assets` 的唯一约束从 `path` 改成 `(project_id, path)`。不复制文件。

素材推荐（现在按文件名、同目录去猜）只在当前项目的素材里找。

### 3.3 列表上怎么认

单项目模式下，不在每行再写项目名。

全部项目模式下：

- 内容行、任务卡、日历条：名称前 8px 颜色点，tooltip 是项目名
- 素材格：缩略图角上同样的颜色点
- 筛选条增加项目多选。从「全部」收窄时用它，不必先回顶栏

插件侧栏顶部同样放项目名按钮，选项与桌面端同步。今天接口默认带当前 `projectId`。不这样做的话，桌面分开了，插件里又混在一起。

## 4. 一条内容上的三个字段

标题、正文、关联词属于同一条内容，也属于这条内容下的每一个渠道任务。任务不各自再存一份文案。改内容，各渠道任务看到的是同一份。

### 4.1 库里的形状

`content_items.title` 继续当标题。`fields_json` 扩成：

```json
{
  "title": "本地发布台账，发完自己回填",
  "body": "正文 Markdown，不含标题行，不含关联词那一段",
  "keywords": ["local-first", "content calendar", "发布台账"]
}
```

`keywords` 是字符串数组，不带 `#`，不加渠道格式。展示和复制时再格式化。空数组合法。

旧数据没有 `keywords` 时，打开条目不自动改正文。检查器里给一句「从正文识别关联词」，用户点了才抽，抽完可以撤销。批量识别放在内容列表的多选操作里，只处理还没有关联词的条目。

### 4.2 导入时怎么认

认完要在预览里看得到，确认后才入库。预览每一条仍然是一张卡片，里面三栏，而不是三条记录。

**Markdown / Word / 纯文本（沿用现有拆分，拆分单位不变）**

一块内容进来之后：

1. 标题沿用现在的标题：拆分标题，或文首第一个一级标题。标题行从正文里拿掉。
2. 关联词按下面顺序找，找到一处就停，避免正文里的普通「标签」小标题被误伤：
   - 文首 frontmatter 的 `keywords` / `tags` / `关联词` / `关键词`
   - 单独一段，行首是这些词之一，后面跟冒号：`关联词`、`关键词`、`标签`、`话题`、`Tags`、`Hashtags`、`Keywords`。站外文案包里的写法 `**关联词：** \`local-first\` · \`content calendar\`` 走这一条
   - 全文最后一段，且这一段里至少 70% 的词是 `#词`，或是用 `·` / `|` / 顿号隔开的短词（每个词不超过 30 字，没有句号）
3. 找到的那段从正文删除。词按 `#`、反引号、`·`、`|`、顿号、逗号、换行切开，去掉空词和重复。
4. 没找到就留空。不猜测正文中间的词。

**表格（CSV / Excel）**

在现有标题列、正文列之外，识别关联词列。表头命中：`关联词`、`关键词`、`标签`、`话题`、`keywords`、`tags`、`hashtags`。预览里让用户改列映射，和现在改标题列、正文列一样。一行仍然是一条内容。

**认错了怎么办**

预览卡片三栏都可以改。关联词是 chip，退格删除，回车新增。若识别把正文末段吃进了关联词，卡片上有「放回正文」。确认导入之后，检查器里仍可改这三栏，改的是库里的字段，不回写用户的源文件。这和现在「删条目不动 Markdown」一致。

### 4.3 检查器里的样子

文案页不再是一个按钮加一大段预览。三块叠在一起，每块右上角一个复制：

```text
标题
本地发布台账，发完自己回填          [复制]

正文
…… Markdown 预览 ……               [复制富文本]

关联词
local-first   content calendar   发布台账
                                       [复制]
```

正文的复制保持现在的富文本（HTML + 纯文本），按钮仍是这一页唯一的主按钮。标题和关联词是次按钮，复制纯文本。

没有关联词时，第三块显示「还没有关联词」，复制按钮禁用。不要复制出空字符串让用户以为成功了。

### 4.4 任务上的复制：单字段，和依次粘贴

只加三个按钮，用户对着平台上的三个框来回点，仍然容易贴错格。任务条（今天、任务、插件）用两种动作。

单字段，随时能点：

- 复制标题
- 复制正文（富文本）
- 复制关联词

0.3.6 没有做下面的依次粘贴。桌面端是四个复制按钮：复制标题、复制正文、复制关联词、复制全文。复制全文是标题、空行、库存正文、空行、按渠道格式化的关联词，纯文本。下面几段留作当时的取舍记录。

依次粘贴，是一个进度，不是第四份文案：

```text
依次粘贴    ① 标题  →  ② 正文  →  ③ 关联词
            已复制标题。贴到小红书的标题栏，再点下一步。
```

每点一次，把当前这一格放进剪贴板，并前进。三格走完，按钮变回起点。用户中途改去单字段复制，进度取消，避免下一跳突然变成正文。

这一步只操作剪贴板。插件不往小红书、Pinterest 的输入框里写字。

关联词出剪贴板时按渠道格式化。库里仍然是不带符号的词：

| 渠道 | 剪贴板内容 | 贴到哪里（写在按钮旁的一行字里） |
|------|------------|----------------------------------|
| 小红书 | `#本地优先 #内容日历 #发布台账` | 话题栏。词与词之间一个空格 |
| 抖音、快手、视频号、TikTok、Instagram | 同上，`#词` 空格分隔 | 文案末尾或话题区。Instagram 超过 5 个时，按钮旁写「已有 N 个」 |
| Pinterest | `local-first, content calendar, 发布台账` | 描述栏后部，或你自己的关键词区。标题用「复制标题」，不要和描述混在一次 |
| 微信公众号 | 不自动加 `#`，用中文顿号：`本地优先、内容日历、发布台账` | 选填。很多篇不贴标签 |
| Reddit、知乎、Product Hunt | 同样顿号或逗号，不加 `#` | 一般不贴。按钮仍在，避免找不着 |
| 未选渠道（内容库） | 原样，空格分隔，不加 `#` | 内容库没有渠道上下文 |

Pinterest 任务多一个「复制替代文本」。内容上没有单独的 alt 字段时，用标题填充，旁边注明「用的是标题」。以后若要单独的 alt，再加字段，这次不加。

字数：小红书标题旁显示 `n/20`，Pinterest 标题旁显示 `n/100`，描述 `n/500`。超出用现有警告色，不截断，不阻止复制。截断会把用户没看见的字弄丢。

渠道发布包里的 `标签.txt` 改为写出这份关联词的渠道格式。没有关联词时，文件里写「（这条内容还没有关联词）」，删掉现在的 `#话题1 #话题2` 占位，避免打包之后当成真标签贴出去。

插件侧栏每个任务三粒按钮，全宽排列，顺序与桌面端相同。依次粘贴放在三粒按钮下面。

## 5. 大图在关联时看得到

### 5.1 现在为什么是空的

`media.rs` 用 `ImageReader::open` 后 `decode()`，再 `thumbnail(320)`。`image` 0.25 默认只允许大约 512MiB 的解码分配。一张边长很大的 PNG、一张拼起来的长图，像素 × 4 再加解码器自己的缓冲，就会失败。

失败被丢掉，磁盘上没有 webp。`MediaThumb` 看到没有 `thumbPath`，画一个 `◻`。关联对话框里于是只剩文件名和一整行路径。文件名经常是导出序号，没法决定要不要勾。

列表用的是这张小图，不是原图。原图继续留在用户目录。

### 5.2 生成规则

每张图先读文件头里的宽高（JPEG 的 SOF、PNG 的 IHDR），这一步不解码像素。宽高写入 `media_assets`。技术标准里本来就有这两列，迁移 `004_media.sql` 还没有。

然后：

1. 估算 RGBA 不超过 48MiB 的，沿用现在的解码再缩小，写成 320px 的 webp。
2. 更大的，不整图解码。Windows 上用系统缩略图（`IShellItemImageFactory::GetImage`，资源管理器同一套）取一张约 256px 的图，再存成 webp。
3. 系统缩略图也没有时，标记失败，到此为止。不在后台把内存上限放开重试。
4. 单张自动预览超过 3 秒就放弃这一张，继续下一张。一张大图不能堵住同批剩下的图。
5. 状态记下：`pending`、`ready`、`failed`。失败原因用短句，例如「图太大，没有生成预览」。

长图判定：高 / 宽 ≥ 2.2。缩略图用顶部对齐（`object-position: top`），因为营销长图的字多在上半。居中裁切会正好切掉标题。

### 5.3 卡片上始终有字

关联对话框、素材页、检查器里的素材，用同一种卡片。没有预览时也不许只剩一个空方块。

```text
┌──────────────┐
│  预览或骨架   │  长图
│              │
└──────────────┘
春季上新-03.png
1242 × 4968 · 8.6 MB
```

三种状态：

| 状态 | 图的区域 | 底下的字 |
|------|----------|----------|
| 生成中 | 灰色骨架，不转动全屏 | 文件名、若已读到则加上宽高和大小 |
| 已有预览 | 小图。长图顶部对齐，角上写「长图」 | 文件名、宽高、大小 |
| 失败 | 图区域写「预览没有生成」，不要用空方块 | 文件名、宽高、大小、原因。按钮：「打开原图」 |

勾选与预览无关。预览失败的图仍然可以关联。打开原图用系统看图，看完回到对话框，勾选状态还在。

点预览区域打开本应用内的一张大一点的预览（约 720px 宽，同样顶部对齐）。没有小图时，这个点击改为打开原图。不在列表里加载原图。

素材页筛选项增加「预览失败」，方便把以前没生成出来的图集中打开看一次。修复生成逻辑之后，提供「重试预览失败的图」，只跑 `failed`，不把整个库再解一遍。

## 6. 四件事串起来的一次操作

以「给已经上线的两个产品发站外稿」为例。

1. 顶栏从「发稿匣」换到「彭兔子制版」。内容、素材、今天、插件里的列表一起换成这个产品。
2. 来源页看到「导入到 彭兔子制版」。扫该项目的文案目录，或丢进一份表格。预览里每一行是一张卡片：标题、正文、关联词。确认后仍是一条内容。
3. 素材页只看到这个项目的图。大图即使预览失败，也能看到 `1242 × 4968 · 8.6 MB` 和「打开原图」。确认是那张春季长图后再关联。
4. 今天里打开这条任务。小红书用复制标题、复制正文、复制关联词分别贴到标题栏、正文、话题栏。Pinterest 同样三次，对上官方发布页的 Title、Description，关联词按逗号放进描述。需要整段时用复制全文。

发完仍在平台自己的页面回填链接。项目只决定「这是哪个产品的台账」。

## 8. 验收

做完之后用这几条看，不看界面好不好看。

1. 新建两个项目，各导入一份文案和一组图。不切换时，内容列表和素材列表里看不到另一个项目的文件。
2. 顶栏切到另一个项目后，桌面今天列表和插件今天列表同时换成那一个。切到「全部项目」时，两行能靠颜色点分开。
3. 一份带 `**关联词：**` 的 Markdown，以及一张含「标题 / 正文 / 关联词」三列的表，导入预览里是一张卡片三栏。入库后仍是一条内容、一个 id。
4. 小红书任务上，「复制标题」只出标题，「复制正文」不含关联词那一段。点「复制关联词」后选「加 #」，得到空格分隔的 `#词`。井号选择、复制全文和日历导出的验收见 [排期导入与复制格式方案](PublishKit-排期导入与复制格式方案.md)。
5. 放进一张会让现在的 `decode()` 失败的大图（宽或高很大，或文件在几十 MB）。关联对话框里能看到宽高和文件大小。预览成功时能看出是哪张，尤其长图能看到上半部分。预览失败时有「打开原图」，并且可以勾选关联。
6. 这一张大图生成失败时，同一批里其余小图仍有预览。
7. 删除或移动项目归属后，用户磁盘上的 Markdown 和图片还在原路径。

## 9. 建议的实现顺序

三块已在 0.3.5 落地。0.3.6 用复制全文替换了第 2 步里的依次粘贴。下面保留当时的拆分方式。

三块可以分三次做，每次都能单独使用。

1. 项目表、迁移、顶栏切换、列表和导入的项目过滤，插件今天列表跟着走。做完，两个产品的素材不再混在一个列表里。
2. `keywords` 字段、导入识别、三按钮、依次粘贴、发布包 `标签.txt`。做完，粘贴时不用再从一段富文本里自己摘。
3. 宽高与预览状态、系统缩略图、关联卡片。做完，大图在勾选前能判断是不是那一张。

第 1 步会碰到现有数据和备份格式，放在最前。第 3 步不依赖第 2 步。
